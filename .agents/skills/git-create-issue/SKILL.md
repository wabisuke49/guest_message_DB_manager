# GitHub Issueの作成

入力されたテキストまたはファイルを理解し、必要なら関連するコードと既存Issueを確認して、実装可能な単位のIssueに分ける。

## 作成前の確認

- `.github/ISSUE_TEMPLATE/` にあるテンプレートのうち、最も適したものを読む。本文ではYAMLフロントマターを除く。
- `gh issue list` 等で既存Issueを確認し、重複を作成しない。重複があれば、更新と新規作成のどちらが適切かをユーザーに提案する。
- 内容が既存テンプレートに合わない場合は、新しいテンプレートまたはラベルの追加を提案する。
- 複数Issueに依存関係がある場合、依存先から作成する。

## 作成方法

- Issueのタイトル、本文、ラベル、担当者を決め、作成予定をユーザーに提示して確認を得てから作成する。
- シェル展開や引用符の問題を避けるため、本文は安全な一時Markdownファイルに書き出し、`gh issue create --body-file <path>` で作成する。
- 作成後はIssueのURLを報告し、一時ファイルを削除する。

## 境界

このスキルはIssueの作成だけを扱う。コード変更、コミット、プルリクエストの作成は行わない。
