# フェーズ1：メール受信とデータ抽出

## 目的

SMTPサーバーでメールを受信し、解析前の生メールを確実に保存する。
固定されたメール本文のフォーマットから必要なフィールドを抽出してJSON化し、フェーズ2のメッセージ受信サーバーへAPIで送信する。

フェーズ1は、メールを起点とするデータを失わずにフェーズ2へ渡すための入口を担う。

## 対象範囲

```text
送信元メールシステム
  ↓ SMTP
メール受信サーバー
  ↓
生メールを保存
  ↓
本文フォーマットを解析してフィールド抽出
  ↓
メッセージJSONを生成
  ↓ HTTP API
フェーズ2：メッセージ受信・保存・単体分析サーバー
```

対象外：

- 受信したJSONのメッセージDBへの保存と単体LLM分析（フェーズ2）
- SessionID単位の会話全体の分析、要約、Embedding（フェーズ3）
- Directusなど送信元システム側のメール生成・配信
- 検索UI、類似検索、RAG

## 大まかな計画

| フェーズ | 実施内容 | 主な成果物 | 完了条件 |
| --- | --- | --- | --- |
| 0. 受信・抽出仕様の確定 | 送信元、SMTP受信条件、対象メールの判定条件、本文フォーマット、抽出フィールドを整理する | メール仕様、JSON契約 | どのメールをどのJSONへ変換するか合意できている |
| 1. SMTP受信基盤 | SMTPサーバーの起動、ポート・ネットワーク設定、基本ログ、ヘルスチェックを整える | 常駐SMTP受信サービス | テストメールを受信できる |
| 2. 生メール保存 | ヘッダー・本文・添付情報などを解析前に保存し、受信IDと時刻を記録する | 生メール保存処理 | 解析・送信に失敗しても元メールを確認できる |
| 3. メール解析 | MIMEメールを扱い、対象の本文を取得する。固定フォーマットから必要な項目を抽出する | パーサー、入力バリデーション | 正常メールから必要フィールドを安定して取得できる |
| 4. JSON生成 | 抽出結果をフェーズ2との契約に従うJSONへ正規化する | JSON変換処理 | `SessionID` を含む必須フィールドを満たしたJSONを生成できる |
| 5. フェーズ2送信 | フェーズ2のAPIへ送信し、送信結果を記録する | APIクライアント、送信ログ | JSONがフェーズ2へ届き、受理結果を確認できる |
| 6. 障害対応 | 解析失敗、API送信失敗、重複メール、再送を扱う | エラー記録、再送処理 | メールを失わず、問題のあるメールを再処理できる |
| 7. テスト・受入 | 正常・異常・再送を含むサンプルメールで一連の流れを検証する | fixture、単体・統合テスト | SMTP受信からフェーズ2への送信まで再現できる |

## 処理の方針

1. メールをSMTPで受信する。
2. 受信直後に、生メールを改変せず保存する。
3. メールの送信元・件名などから処理対象かを判定する。
4. MIME構造から本文を取得し、固定フォーマットを解析する。
5. 抽出項目を検証し、フェーズ2のAPI契約に沿ったJSONへ変換する。
6. フェーズ2の受信APIへ送信する。
7. 成功・失敗を受信メールの記録に紐付けて保存する。失敗時は再送可能な状態にする。

## 抽出・送信データの方針

| 項目 | 方針 |
| --- | --- |
| 生メール | 本文の解析前に保存する。元データを上書きしない |
| 受信識別子 | メールごとの一意なIDを発行し、保存・解析・送信結果を紐付ける |
| `SessionID` | 本文から抽出し、フェーズ2へ送るJSONの必須項目とする |
| 抽出フィールド | フェーズ2でメッセージ保存に必要な項目へ正規化する |
| 送信先 | フェーズ2のメッセージ受信API。認証・タイムアウトは設定で管理する |
| 送信結果 | HTTPステータス、送信日時、失敗理由、再送回数を記録する |

## 失敗時の扱い

| ケース | 扱い |
| --- | --- |
| SMTP受信後の保存失敗 | 受信成功応答を返す前に扱いを明確化し、データ損失を避ける |
| 本文形式が想定外 | 生メールと解析エラーを保存し、フェーズ2へ不完全なデータを送らない |
| 必須項目の抽出失敗 | エラー状態として記録し、フォーマット修正後に再解析できるようにする |
| API送信失敗 | 生メール・抽出済みJSONを保持し、再試行または手動再送できるようにする |
| 同一メールの重複受信 | メール固有の識別子などで判定し、フェーズ2側でも冪等に処理できる形で送る |

## 要検討事項

- SMTPサーバーの公開方法、TLS、送信元制限などのセキュリティ方針
- 生メールの保存先、保存形式（例：EML）、保存期間、個人情報の保護方針
- 添付ファイルを保存・送信対象に含めるか
- HTMLメールとプレーンテキストメールが混在した場合の本文選択ルール
- 対象メールを判定する送信元・件名・ヘッダー条件
- 本文フォーマット変更への対応、抽出ルールのバージョン管理
- フェーズ2 APIの認証、タイムアウト、リトライ回数、応答仕様
- 重複判定に使用するメール固有IDと、フェーズ2側の冪等性キー
- 解析・送信失敗メールの確認方法と、手動再送の運用

## 完了時の状態

1. SMTPサーバーが対象メールを受信できる。
2. 受信した生メールを、解析前に確認・再処理可能な形で保存できる。
3. 固定フォーマットの本文から必要な項目と `SessionID` を抽出できる。
4. 抽出データをフェーズ2のAPI契約に沿うJSONとして送信できる。
5. 解析・送信に失敗した場合も、元メールとエラー理由を保ったまま再試行できる。
